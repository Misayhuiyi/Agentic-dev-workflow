# 按风险验收

先核对任务基线、候选、暂存/未暂存/新增文件；无 Git 使用受限文件指纹。分别映射需求到实现和实际检查，不以默认 git diff 代表全部任务。

| 范围 | 证据要求 |
| --- | --- |
| 行为与契约 | 正常/空/错误/边界，真实调用方和向后兼容 |
| 数据与权限 | 事务、重复请求、服务端鉴权、跨租户/用户隔离 |
| 资源与并发 | 超时取消、释放、竞态、重试和副作用 |
| UX | 关键用户路径，加载/错误/空态与不同尺寸 |
| 可访问性 | 键盘顺序、焦点、语义和标签、对比度；辅助技术检查注明实际工具与范围 |
| 构建与部署配置 | 锁定依赖、配置来源和真实产物；不执行发布 |

只读审查零写入。发现格式：严重性、文件/行、可观察影响、证据、置信度及建议验证。不能边审查边修复；没有独立执行者标自审。

从真实配置/CI 确定命令，执行前核对外部服务、费用与数据副作用。工具不可用就报告未执行，不能凭主观观感声称 E2E、无障碍或质量通过。区分任务回归、已有失败和环境限制，不顺手修无关模块。
