# 事实、预期与历史

当前代码/配置定义实际实现，已批准需求/契约定义预期，测试/运行记录提供有限观测。冲突要明确具体差异，不将聊天或状态摘要置于实际证据之上。

计划能力标计划/未实现；已观察事实附来源和范围，估算附方法/区间，假设附验证方法，说明性示例显式标示；未知与未验证明确写出。不得把行业数据、Mock 或示例当作本项目的业务基线、运行结果或收益。提交 SHA 不能代表 dirty 工作区，验证绑定相关文件指纹。

文档的 owner/status/version/evidence/open_questions 分别回答谁维护、合同/记录是否批准或替代、哪个版本、依据和未决项；任务执行动态状态仍以原 task-state 为准。合同版本或准则变化需核对受影响决定与证据，不自动刷新批准/人工验收。

追溯使用稳定 ID 和链接，不复制上游事实：业务问题及基线 → 需求/验收 → 决定 → task → 当前代码/产物候选 → 测试/Eval/UAT → release → 业务结果。未发生、缺证据和不适用须分开；技术验证、原型认可、人工接受、已发布、实际收益分别陈述，不跨阶段推断成功。

ADR 保留当时背景，以 superseded/已替代和后继链接表达演进。修正笔误可以，伪造历史、删除失败实验、编造测试日期、提交或 benchmark 不可以。

只创建有实际内容和维护用途的记录。不复制完整日志/diff/聊天，不预建空 ADR/runbook。文档命令引用真实配置；核对有权限且无额外副作用后才执行，不为验证文本擅自生产操作。
