# 变更到权威文档

先采用项目已有路径，下表只提供没有约定时的位置；不复制所有模板。

| 变化 | 唯一权威位置 |
| --- | --- |
| 安装、配置、运行、用户操作 | README/使用说明及配置源 |
| 项目目标、当前能力、里程碑、模块或文档入口 | 原项目事实入口；无约定时 docs/project-context.md，只放项目级事实和链接 |
| 接口、事件、字段和错误语义 | 实际 code-first 或 spec-first 契约源，再按真实流程生成 |
| 架构、数据流 | 当前架构说明；长期决定另记 ADR |
| 业务流程/痛点证据、需求、规则、成功/验收指标与设计 | 原 spec/PRD；保留来源、基线、非目标、批准状态及需求/验收 ID，不另造同义合同 |
| 里程碑和实施步骤 | 原唯一 plan；按业务纵向切片，近期细化、远期保留未知，引用 spec，不复制需求 |
| 需求调研证据、候选建议和审核决定 | 原调研记录；无约定时 docs/research/，已接受项链接唯一 spec/plan，待定/拒绝项不进入执行清单 |
| 最小可行性实验及人工业务验收 | 原任务/验证记录中的合同、候选、证据与决定；需要独立长记录时再建 docs/verification/ 并回链，不另建计划 |
| 重要迭代和效果实验 | 原迭代记录或 docs/iterations/；关闭后作为历史快照，未完成项链接活动任务 |
| 任务进度、技术验证、人工接受与恢复/交接 | 原 docs/tasks/<task-id>.md 的唯一 JSON 状态，verification/human_acceptance 分开；人类视图由 project_status.py 生成，交 continuity |
| 活动任务增减、负责人或工作树变更 | 整合者更新 docs/tasks/index.md 的指针，不复制进度 |
| 发布、迁移、恢复、事故 | docs/operations/ 的实际记录与受影响 runbook |
| 问题到业务结果的关联 | 原 spec 的紧凑追溯表仅留稳定 ID/链接：问题证据 → 需求/验收 → 决定 → task → 候选 → 测试/Eval/UAT → release → 结果；各环节事实仍在原权威源 |
| 内部小改或文案链接 | 无文档影响可不更新；链接修复只动目标文档 |

外部文档系统不可访问时报告限制，不能本地造副本冒充同步。生成器或业务源需要改动时检查授权范围；文档任务不能默默变成代码开发。

书面合同确需版本化时标 owner/status/version/evidence/open_questions；这是文档负责人、批准状态和证据索引，不能成为第二份执行状态。原型、PoC、里程碑合同及交付活动只按触发使用；跨阶段缺口需要检查时读[交付活动表](../../../../.ai-workflow/references/delivery-loop.md)，不为小任务补全流程文档。

任务负责人在实际进度、范围、验证或阻塞变化时更新状态，并在暂停/交接前核对。整合者维护项目入口与公共索引。只完成一处小改且无文档影响时无需记录；未完成小任务不能以“小”为由丢失交接事实。已接受 ADR 保留原决策，以新记录和后继链接表达变化。
