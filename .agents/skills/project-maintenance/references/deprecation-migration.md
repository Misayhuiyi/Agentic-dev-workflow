# 弃用迁移

列真实调用方、旧/新契约、兼容窗口及淘汰条件。下游不能同步升级时保留必要的并行兼容，避免把简洁当破坏契约依据。

获准迁移后按依赖顺序更新实现、锁文件、运行时与 CI；生成物从实际权威源和锁定生成器重建。测试必须覆盖旧调用方与新行为，不手改输出掩盖源错误。

明确回退版本和所需数据状态。失败、兼容约束不满足或恢复未验证时停止相应步骤，不用吞异常维持表面成功。记录已改/未改、验证结果及下一负责者。

完全退役服务、Agent、工具或旧接口时，按实际范围补齐关闭条件；评估或迁移批准不自动授权删除数据、撤销凭据或释放资源：

1. 清点实际消费者、在途任务、回调与计划任务，确认替代路径、兼容窗口、迁移证据和消费者签收；未迁移依赖明确保留或阻塞。
2. 明确数据导出、保留期限、删除范围和授权依据，核对副本/缓存/索引的处置及无法删除部分。不以停止服务推定数据已清除，也不以备份存在代替可恢复证据。
3. 按依赖顺序停止入口、新任务、调度和回调，处理在途/不确定结果后撤销退役对象的凭据/权限；共享凭据先核对其他使用者。停止无用告警，保留退役观察所需的监测，避免在观察前失去证据。
4. 核实资源释放、订阅/计费关闭和残留费用，而非只删除本地配置。破坏性或付费动作仅在明确授权内执行。
5. 完成约定观察窗口，确认无遗留调用/任务和未解释费用，由负责人及适用消费者签收；未达成项保持待办。实际动作、证据与剩余影响写入原[运维记录](../../../../.ai-workflow/templates/operations-record.md)，不把计划写成已退役。
