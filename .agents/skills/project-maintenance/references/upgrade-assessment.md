# 升级评估

从实际 manifest、完整锁图、runtime/engine 声明、CI 镜像和生成器查当前版本，区分直接与传递依赖。不能只改 manifest 留下不可复现锁。

对照供应方 release notes、安全通告和兼容声明选择最小修复版本，另列推荐迁移版本、支持周期、收益及风险。不编造版本、CVE 编号或修复结论；离线或资料不可达时记录来源缺口，限制判断。

按安全暴露、契约兼容、迁移成本和恢复能力分级。CVE 不等于系统已受攻击，也不自动要求完整 threat model；与真实暴露面、鉴权、租户或数据边界关联时，才请求 security 的相应范围。

验证安装/锁一致性、受影响测试、构建及 CI/runtime 对齐。操作可能收费、外部写入或改变生产时仍需具体授权。
