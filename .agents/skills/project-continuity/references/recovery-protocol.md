# 七步恢复协议

1. 获取真实目录、Shell、Git 根、分支、HEAD、worktree 与未提交路径；无 Git 明确记录，不初始化仓库或虚构 SHA。
2. 读取项目事实入口及活动任务索引，不加载全部历史。
3. 优先按用户给定 task ID、文件或分支定位任务，核对记录与当前工作区。
4. 无明确选择时，仅在当前分支唯一匹配一个活动任务时自动选择；无 Git 只能依据用户指针或唯一可核实匹配。歧义只问一个决定性问题，不按修改时间猜“最新”。
5. 对照实际代码/配置、已批准 spec/plan 和验证记录检查陈旧状态；记录不符先重建事实。
6. 输出六项：目标、完成项、未提交内容、验证、风险、精确下一步。下一步含验证和停止条件。
7. 只加载下一步必需的 spec、plan、代码与测试，返回原已批准方法链；本协议不授权实施。

任务文件首行 JSON 为唯一动态状态；人类快照从它和当前工作区派生，详细正文不手工维护第二份进度。用 `.ai-workflow/scripts/project_status.py --root . --task <ID> --format markdown` 输出只读视图，在授权内把完整标记区放入任务文档；`--check-view` 检查其是否仍与当前事实一致。没有 Python 时人工核对并标记未自动验证。

已完成的小改不强制留下任务文件。未完成任务在暂停、阻塞或交接时，不论大小均需最小目标、完成项、验证、风险和精确下一步；有写入授权时维护原任务记录，没有原记录才按模板创建，不补造无必要的 spec/plan。无写入授权时只输出六项快照、建议任务路径并明确尚未持久化。

多 Agent 各写已分配任务文件；公共索引只存指针，由整合者在核对实际差异后显式更新。任务完成保持原路径和证据可追溯，从活动索引移除，不以移动文件破坏相对链接。当前控制权或工作区不匹配时保留安全发现结果，停止依赖该选择的操作。
