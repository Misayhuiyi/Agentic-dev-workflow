# 新鲜度与证据

fresh：记录的相关文件指纹与当前事实一致，并且所需证据可获取。stale：相关代码、测试、配置、依赖、任务范围或候选已变化。unknown：基线、文件集合、证据或环境不足，无法比较。unknown 不能当 fresh。

Git 记录真实根、分支、HEAD、worktree 及任务相关暂存/未暂存/新增路径；HEAD 不能代表 dirty 内容。无 Git 记录有限文件集合的相对路径和内容指纹，元数据用于辅助，不虚构提交。

验证必须绑定被测输入。相关输入变化使旧结果可能过期；重跑受影响检查前不要沿用通过结论。任务状态文档或聊天永远不高于代码/配置的实际实现证据；已批准需求定义预期，冲突要解释而非偷偷改需求。

人工验收有独立的候选指纹和准则摘要，不能因技术检查重跑通过而自动刷新。准则摘要绑定目标、验收项及 scope；权威 spec、样本/模型/配置等会影响业务结果的文件按实际需要列入 related_paths。文件/准则变化后旧接受为 stale；缺人工记录或比较依据为 unknown。明确不适用的理由也绑定准则，任务性质变化后重新判断，不沿用旧豁免。

指纹不采集密钥、全文 diff 或整个用户目录。只恢复当前任务，保留其他任务未提交内容与 worktree 边界。
