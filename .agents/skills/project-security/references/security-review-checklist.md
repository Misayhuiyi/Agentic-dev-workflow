# 只读安全审查合同

| 边界 | 检查 |
| --- | --- |
| 身份和对象权限 | 服务端验证身份、角色、对象归属和拒绝路径 |
| 多租户数据 | 查询/缓存/导出/后台任务是否保留租户过滤与隔离 |
| 输入与工具 | SQL、路径、命令、反序列化以及外部内容进入 Agent 工具的边界 |
| 秘密与日志 | 注入来源、最小权限、脱敏和轮换设计，不输出实际值 |
| 依赖与暴露 | 真实锁版本、通告依据、调用路径和可达性 |

涉及 Agent 时按实际边界补查，无 Agent 时不适用：

- 逐工具核对输入/输出、错误与副作用，实际宿主权限、服务端鉴权、凭据范围和付费额度是否与授权相符。Prompt/Skill 的禁止语句是软约束，不能当作隔离、最小权限或费用控制已经生效的证据。
- 外部内容和工具返回的来源、信任等级及租户归属是否保留；检索、缓存、压缩摘要和长期记忆不能跨租户泄漏或把不可信指令升级为授权。
- 上下文压缩是否丢失拒绝条件/授权范围；过期或错误记忆能否纠正、失效和按授权删除。反馈和模型推断不能未经事实确认及审核写入长期记忆或生产规则。
- 每步与总执行预算、循环/超时停止、取消/人工接管是否可验证；有副作用的工具检查幂等、去重和不确定结果的对账路径，不能以自动重试扩大损害。

需要补齐设计时引用现有 [Agent 合同](../../project-development/references/agent-contract.md)，审查本身不授权实现或新建 Agent 基础设施。

每项发现写文件/行、触发条件、影响、证据、置信度及建议验证。确认风险与可利用性未知分开，不靠单条关键词断言漏洞。

只读模式零写入；不运行未授权扫描、攻击流量、生产请求或读取秘密。隔离验证需明确目标和权限。修复只在获准后交 development；不要在审查中悄悄改断言或权限门槛。
