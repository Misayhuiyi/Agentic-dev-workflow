# 按需裁剪的交付活动

仅当新业务闭环、跨阶段依赖或交付缺口需要整体核对时读取。本表是现有生命周期的检查参考，不是第二套流程、计划或批准关卡。普通问答与清晰低风险小改沿原入口完成，不逐行补文档；“不适用/已有证据充分”的理由可留在原合同或回复中，不要求单独报告。

## 共用合同与证据约定

复用唯一 spec/PRD、plan 和 task-state。书面记录仅按需要标负责人（owner）、批准/记录状态（status）、版本（version）、证据链接（evidence）和未决问题（open_questions）；执行动态状态只在 task-state，不能在本表再维护。

一个里程碑是一条可体验、可验收的业务纵向切片，近期细化、远期保留未知。原合同应能回答：目标及范围/排除（scope/exclusions）、要消除的不确定性（uncertainty）、交付产物（artifact）、验收准则和样本/时间/费用上限（acceptance/budget）、依赖与失败回退（dependency/rollback）、负责人和审核/验收人（owner/reviewer）。未知逐项写明，不复制设计和计划。只有产品本身的自主执行、工具或记忆行为受影响时，才另读 [Agent 执行合同](../../.agents/skills/project-development/references/agent-contract.md)，不因用 AI 开发或并行分派而触发。

下表每行都核对触发、输入、工作、最小产物、验证、进入下一活动的条件、负责人、失败退路与跳过理由；共同规则只写在这里。实际决定记继续（go）/调整（adjust）/缩范围（reduce）/停止（stop）及其依据。已有明确授权直接复用；只有新范围、关键条件或额外权限才取得对应决定，不能把活动表当作自动授权。MVP 可以缩范围，不能豁免当前范围内的质量、安全和验收。

| 活动 / 原入口 | 触发与输入 | 工作与最小产物（原位置） | 验证与进入下一活动条件 | 负责人/审核人 | 失败退路 | 跳过理由 |
| --- | --- | --- | --- | --- | --- | --- |
| 业务发现 / kickoff | 新项目、首次接入或目标有缺口；现有材料/流程/代码 | 核对用户、痛点、基线、规则、边界；原 spec 的问题与验收 ID | 区分事实/估算/假设/示例；关键目标与边界可判断 | 任务负责人 / 用户 | 缺关键事实先查证，目标不成立则缩范围或停止 | 目标与合同已有且仍有效 |
| 有界调研 / research | 用户要求或同意补资料；限定问题与访问范围 | 比较证据、适用性和复用成本；原调研记录的候选建议 | 来源可查、局限明确；用户接受项才进入 spec/plan | 调研负责人 / 用户 | 证据不足保留未知；拒绝/待定不实施 | 现有材料足够，或未获调研授权 |
| 产品原型 / 原设计入口 | 交互、流程或人机分工不确定；真实场景与规则 | 优先复用组件；必要时独立 HTML；可体验的原型及真实/Mock 标识 | 观察任务能否完成；按风险覆盖等待/失败/取消/拒绝/人工接管，理解得到确认 | 设计/实现负责人 / 用户或业务代表 | 调整流程或缩范围；不据演示宣称真实集成可行 | 无交互未知；后端不为流程要求造 UI |
| 技术 PoC/Spike / verification | 关键假设只能实测且会改变方案；获准真实样本、环境/预算 | 在上限内验证一个假设；原实验合同和实际证据 | 预定通过/失败线、实际消耗与停止条件；证据支持适用范围 | 实验负责人 / 决定人 | 达上限/失败即停，补证或替代；阻止依赖假设的高成本工作 | 成熟低风险复用，或资料查证已能回答 |
| 需求与设计 / 原设计入口 | 产品、接口、数据或架构重要选择未决；发现/审核/实验结果 | 更新唯一 spec/PRD、取舍与契约源；重要长期决定才写 ADR | 目标、非目标、业务规则、成功/验收指标与兼容影响明确；所需设计决定已取得 | 任务负责人 / 指定审核人 | 退回证据或调整设计，不以计划冒充当前实现 | 清晰局部改动可用已有合同，无需新 spec |
| 里程碑与分派 / development | 复杂依赖或多人执行；已批准范围与验收 | 原唯一 plan 按纵向切片，近详远略；必要的任务执行合同 | 每片有可体验产物、验收/预算、依赖/回退和责任边界；下一片条件明确 | 整合者 / 任务负责人及审核人 | 缩片、串行或调整依赖；不靠新计划掩盖未决设计 | 简单任务在原生命周期内执行，不强制 plan/分派 |
| 实现与集成 / development | 已授权实施；唯一合同、真实工作区/调用方 | 最小闭环到当前切片；相关实现/测试/文档和候选指纹 | 复用已有模式、保护他人改动、适用回归；接口和存量契约不被静默改变 | 实现负责人 / 整合或审查人 | 修根因；授权/契约变化先处理对应决定 | 只读/纯设计请求不实施 |
| 技术测试与 Eval / 原入口或 verification | 行为变化或明确评测；当前候选及固定准则/输入 | 适用测试、审查或 AI Eval；当前环境的结果与失败/未执行项 | 检查通过且证据绑定当前候选；AI 仅在相关时核对模型/提示/工具/数据 | 验证负责人 / 所需独立审查人 | 修复后重测受影响项；不可测明确局限，不能造通过 | 专项 Eval/独立审查不适用可跳过，必要回归不能省 |
| 人工业务验收 / verification | 新模块或显著业务流程；技术结果与可操作候选 | 入口/步骤/样本、真实/Mock、预期/实际、证据、失败/未验证项和待确认点 | 用户/指定验收人明确接受当前候选；未回复/附条件未闭合仍待验收 | 任务负责人 / 用户或指定验收人 | 退回修复/调整/缩范围/停止；独立且已授权工作可继续 | 无业务效果变化才记具体 not_required 理由 |
| 发布与恢复 / release | 用户要求发布准备或已明确授权执行；已验收候选及环境 | 发布/迁移/回退合同、操作证据与观测；原 operations 记录 | 目标环境、权限、门槛和回退可核对；只有所需发布授权具备才执行 | 发布负责人 / 环境授权人 | 达停止条件就停，按已授权回退；事故交 incident-response | 未要求发布时只交付候选，不编造 release |
| 业务结果与下一迭代 / 当前请求入口 | 约定观察窗口到达或用户要求复盘；真实发布/使用证据 | 对照业务基线与目标，记录范围/局限；链接下一决定/任务 | 实际结果与估算分列；据证据决定 go/adjust/reduce/stop | 结果负责人 / 业务决定人 | 未观察保留未知；不获授权不监控、不写生产、不擅开下一轮 | 尚未发布/未到窗口或本次无业务结果变化 |
| 迁移与退役 / maintenance、release | 服务/契约需迁移或结束；消费者、数据、成本与授权范围 | 原运维记录保存迁移/保留删除、凭据、作业回调、资源关闭证据 | 消费者迁移、观察窗口与负责人签收；按[弃用迁移](../../.agents/skills/project-maintenance/references/deprecation-migration.md)核对 | 维护负责人 / 消费者与授权人 | 未迁移依赖、未知恢复或未授权删除则停；保留必要兼容 | 无淘汰/迁移需要 |
| 专项风险与连续性 / 对应生命周期 | 安全边界、依赖、文档事实变化、暂停/交接或生产事故；对应现状 | 仅加载 security/maintenance/docs/continuity/incident 等适用入口；更新各自原权威记录 | 各入口所需证据与边界成立；暂停时可从真实任务状态恢复 | 当前负责人 / 对应授权人 | 停止受影响操作、留精确缺口与恢复条件 | 无相应变化，不为凑阶段执行专项流程 |

技术 PoC 与产品原型若回答独立问题可以并行，结果互不替代。原型认可、技术通过、人工接受、已发布与业务收益是不同事实；真实样本/依赖不可用时保留缺口，Mock 只支持其实际覆盖的局部检查。

安全、适用测试/Eval、可观测性和运维恢复从设计及每个切片开始准备，不留到最后补课。合并不等于部署，部署不等于全量开放，灰度通常已经在生产；具体受控放量与权限见 release。运行反馈先确认事实、分类和改进假设，再测试/评测、审核和发布，不直接写入生产规则或长期记忆；实际价值按[迭代的 Impact Log](../templates/iteration.md)记录。

追溯放在原 [spec](../templates/spec.md)，仅链接“业务问题/证据 → 需求/验收 ID → 决定 → task → 代码/产物候选 → 测试/Eval/UAT → release → 业务结果”。记录尚未发生的环节，不预建空文档；动态状态继续使用原 task-state。
