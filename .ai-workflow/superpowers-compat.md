# Superpowers compatibility contract

Project authorization, `AGENTS.md`, current facts, and approved project documents take precedence over method Skills.

- Superpowers never grants permission to commit, push, open a PR, merge, deploy, delete data or worktrees, modify production, or use paid services.
- Preserve user and other-agent changes. Stop before an overlapping or destructive write whose target is not proven safe.
- Reuse the project's authoritative spec and plan; do not generate a second pair for the same task.
- Before orchestration, identify approved milestone/task IDs, spec/plan revision, exclusions, evidence gates, budget and allowed operations. Pass this bounded slice (with a link to the one plan), not an unapproved future backlog. “Execute all tasks” means all tasks in that authorized slice; an explicit multi-milestone approval does not waive dependencies or human gates.
- SDD controller rulings, review-iteration caps and `parked_with_ruling` cannot waive acceptance criteria, security failures, rejected business assumptions or missing human acceptance. Stop affected dependent work when those gates fail; report unresolved findings and continue only independent authorized work. Never silently lower a threshold to fit an iteration cap.
- `.superpowers/sdd/.../progress.md` is a method execution ledger, not a second project task state or approval source. Recovery first reconciles the project task, workspace and applicable approved plan. Check ledger identity (task, full plan path/revision, worktree); basename collisions or mismatches block reuse. Review committed, staged, unstaged and relevant new files: a helper's `base..HEAD` diff alone omits dirty candidate changes. Helpers do not allocate authorized work or enforce approvals.
- Apply root task sizing before choosing methods. Conversation, knowledge questions, read-only explanation and status lookup use relevant facts without automatic workflow loading. Clear, authorized, low-risk local actions use one project Skill with applicable regression checks, root-cause evidence and fresh verification; they automatically load no Superpowers method. These quality requirements remain binding without a separate method document.
- Substantial complexity, high risk, or an unresolved cause after focused inspection selects only the applicable method for the current stage. An explicit request to apply a named method also selects it; mentioning its name in a question does not. The 14 method descriptions and entry boundaries are locally patched to enforce this scope. Inside a selected method, its later “always/required” language applies only to that method's scope; every nested method must still fit the current stage.
- `using-superpowers` is optional help for method selection or integration troubleshooting, never a prerequisite for starting a session, responding, inspecting files or using project Skills. It contains no universal “always/1%” discovery requirement. Higher-priority host instructions still apply.
- References written `superpowers:<name>` select the sibling project-local `.agents/skills/<name>/SKILL.md`, not a namespaced global plugin. An independently installed plugin has its own metadata and may retain broader triggers. Project changes do not rewrite that plugin's cache or hot-reload an existing session's catalog; verify the effective source in a fresh session. Existing user instructions about light tasks must be honored within the host's instruction hierarchy.
- Simple work stays in the current task without an execution wrapper. Plan orchestration, parallel agents and independent formal review are chosen for actual dependency, risk and review needs, not because the tools exist.
- Multi-agent work, worktrees, local servers, browsers, and network access are conditional on host support, task fit, and authorization.
- Treat Bash examples as Bash; on Windows, translate only after confirming the actual shell rather than presenting them as native PowerShell.
- Resolve relative resources from the canonical Skill directory. `.agents/skills/` remains the complete source; adapters are generated proxies.
- The brainstorming visual companion is optional. Network access, remote resources, and telemetry are disabled by default unless explicitly enabled in scope.

The bundled runtime resources derive from Superpowers 6.3.0 at commit `b36e0829c6d0140e93cfef2ca599b1b07d4a7797`: 46 upstream-derived files plus 14 separately identified UI metadata files. All 14 Skill entrypoints have recorded project activation patches; the other resources retain upstream bytes. Five unreferenced development-only files are omitted; see the source lock and patch record. Installed plugins with similar names do not replace these pinned project sources. Source updates require review of file additions/removals, executable modes, network endpoints, hooks, default writes and local patches.

On hosts without multi-agent or worktree capabilities, execute the same authorized plan serially. Non-Git projects remain non-Git unless explicitly authorized otherwise. Generated Claude proxies and Gemini imports are discovery adapters, not copies of method rules; static generation is not runtime acceptance. See the root README for the actual tested scope and limitations. Template-development tests and historical runtime experiments are kept outside this project foundation.

The milestone protocol is a behavioral soft constraint. Do not claim that this document, the SDD ledger or the read-only completion checker provides a programmatic permission barrier. Stronger task dispatch, authenticated approvals or environment-bound release checks are separate integrations, not silently added by this template. The project-level contract is maintained here; upstream-derived files and their provenance remain separate.
